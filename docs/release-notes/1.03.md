# Fidelya 1.03 (versionCode 4)

## Notes de version — Play Console

### fr-FR

```
Nouveautés de la version 1.03 :
• Nouveaux formats de codes-barres pris en charge : ITF (cartes de fidélité ITF-14), UPC-A, UPC-E, Code 93, Codabar et Aztec. Les cartes qui refusaient de s'importer sont désormais reconnues.
• Fiabilité du scan améliorée : un code non pris en charge n'est plus enregistré sous un mauvais format, le scan continue jusqu'à détecter une carte lisible en caisse.
• Améliorations techniques et optimisations diverses.
```

### en-US

```
What's new in 1.03:
• New supported barcode formats: ITF (ITF-14 loyalty cards), UPC-A, UPC-E, Code 93, Codabar and Aztec. Cards that previously refused to import are now recognised.
• More reliable scanning: an unsupported code is no longer saved under the wrong format — scanning continues until a card that can be displayed at the till is detected.
• Technical improvements and various optimizations.
```

## Détails techniques

- versionCode : 3 → 4
- versionName : 1.02 → 1.03
- Nouveau registre centralisé `SupportedBarcodeFormats` : source unique pour les options du scanner, le nom de format persisté et le rendu à l'écran (`SupportedBarcodeFormats.kt`, PR #1)
- Formats pris en charge : 7 → 13 (ajout de `UPC_A`, `UPC_E`, `CODE_93`, `ITF`, `CODABAR`, `AZTEC`)
- Suppression des repli silencieux vers `QR_CODE` dans `ScanViewModel` et `CardDetailScreen` : un format inconnu renvoie désormais `null` au lieu de produire une carte illisible en caisse
- Couverture de tests : décodage de photos réelles via ZXing (fixtures ITF et EAN-13) avec redressement et étirement de contraste, plus un test épinglant les 13 formats
- Correctifs d'infrastructure de test : noms de méthodes `androidTest` en camelCase (contrainte DEX < 040 avec minSdk 26) et script `scripts/prepare-emulator.sh` pour déverrouiller l'émulateur avant les tests Compose
